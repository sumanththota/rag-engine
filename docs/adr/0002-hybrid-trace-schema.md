# Hybrid schema for the traces table: flat columns + JSONB steps

Considered four shapes for storing Traces: a single JSONB blob per row, a fully normalized `traces`/`trace_steps`/`annotations` set of tables, an append-only event log (one row per step/edit), and a hybrid. Picked the hybrid: `trace_id`, `created_at`, `question`, and the Annotation fields (`status`, `note`, `tags`) as first-class flat columns, with the pipeline's Steps (rewrite/retrieve/generate) stored as one `steps jsonb` column. Flat columns because Annotation writes are plain `UPDATE`s and need to be trivially filterable/indexable; JSONB for `steps` because that shape is expected to grow (new step types like `tool_call`/`tool_response` later) without a migration each time. Rejected full normalization as more migration ceremony than a solo-dev Phase 1 needs, and rejected a single blob because it would make Annotation updates and filtering awkward (`jsonb_set` instead of a plain column `SET`).
